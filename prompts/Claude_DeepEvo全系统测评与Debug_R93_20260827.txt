============================================================
十、最终汇报顺序
============================================================

最终只按以下顺序汇报：

1. 一句话总判定
2. 当前权威生产状态表
3. 实际执行的命令与测试结果
4. P0/P1/P2/P3 Findings
5. 已实施的本地修复及文件清单
6. 生产包与当前源码一致性
7. 六赛数据/HPC/训练边界
8. 能力评分表
9. GO / HOLD / NO-GO 分层判定
10. 剩余风险与下一步三项行动

必须明确区分：

- SOURCE VERIFIED
- TEST VERIFIED
- PACKAGE VERIFIED
- PRODUCTION VERIFIED
- LIVE EXTERNAL UNVERIFIED

不能说“所有功能正常”，除非逐项有当前证据。

十一、开始执行时的首条回复格式
============================================================

开始后先只回复以下结构，再执行 Phase 0：

```text
已进入 DeepEvo R93 全系统独立测评。

当前边界：
- 只读恢复上下文与冻结证据
- 不恢复 cancelled Run
- 不连接 HPC / Chrome
- 不调用 competition 或训练工具
- 不部署、不 commit、不清理脏工作树

第一步将生成：
1. 当前生产/本地/历史三层证据表
2. R93 包与 manifest 独立复核
3. 测试矩阵和风险优先级
```

随后持续执行，不要每一步都等待确认。只有当下一动作需要外部系统、生产变更、凭据、Chrome、HPC、worker 控制、部署、提交或用户业务选择时，才停止并请求精确授权。

不要把“任务很复杂”当成停止理由。先完成所有安全、只读、本地可执行的工作，再汇报真实 blocker。
