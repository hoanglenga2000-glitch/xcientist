# 老师材料解读与改进清单

## 老师实际发了什么

1. `arXiv:2410.20424`：AutoKaggle，多 Agent 自动化 Kaggle 数据竞赛框架。
2. `multimodal-art-projection/AutoKaggle`：AutoKaggle 代码仓库。
3. Kaggle competitions 页面：用于选择正在进行或已结束比赛评测系统。
4. `arXiv:2605.23204`：AutoResearch AI 综述，说明 AI 科研自动化的整体方向。
5. `arXiv:2411.03562`：Agent K 论文，说明更强的 Kaggle Agent 方向。
6. `huawei-noah/HEBO/Agent_K`：Agent K 代码和文档。

## 这些材料共同指向的任务

老师想让我做的不是“训练一个 Agent 模型”，而是建设一个科研数据任务 Agent 工作站。

这个工作站要能完成真实数据任务，并且能用 Kaggle 或老师案例来评测。核心是工作流、工具链、实验执行、结果验证和复盘，而不是从零训练大模型。

## 为什么不能直接复刻已有项目

### AutoKaggle 的问题

- 主要聚焦表格数据，不能直接覆盖所有科研任务。
- 需要手动准备 overview.txt、train/test/sample submission。
- 结果不是 100% 成功，valid submission 仍有失败。
- 特征工程工具过复杂时会增加调试难度。
- 仓库中 API key 文件形式不适合作为我的安全实践。

### Agent K 的问题

- 部署复杂，需要 Kaggle API、登录信息、geckodriver、Firefox、raw data 路径和多个环境。
- full pipeline 时间预算、GPU、leaderboard 和提交机制比较重。
- 适合作为长期目标，不适合作为第一阶段直接完整复刻。

### 泛泛 AI Scientist 的问题

- 科研自动化容易变成概念展示。
- 如果没有证据保存、数据版本、实验日志和复现机制，结果很难被老师认可。
- 对我当前阶段来说，结构化、可执行、可快速验证的 Kaggle 数据任务更适合作为切入点。

## 我应该怎么改

1. 把计划从“通用 AI 工作站”改成“对标 Kaggle Agent 的科研数据任务工作站”。
2. 第一阶段只做表格类任务，降低不确定性。
3. 输入格式按 AutoKaggle 准备：overview、train、test、sample submission。
4. 工作流按六阶段组织：背景理解、EDA、清洗、特征工程、建模、报告。
5. 加入 Agent K 的 scaffold 思路：先生成解题脚手架，再执行和迭代。
6. 必须加入 submission 格式检查和实验日志。
7. 必须记录失败原因，形成可复用经验。
8. GPU 只放在后续模型训练和超参数搜索阶段。

## 第一阶段最小可行任务

选择一个表格类 Kaggle 比赛，优先级如下：

1. Titanic：最简单，适合验证工作流。
2. House Prices：回归任务，适合验证特征工程。
3. Obesity Risk 或 Bank Churn：更接近 AutoKaggle 的 recent tasks，适合验证泛化。
4. 老师提供的真实案例：适合验证科研应用价值。

第一阶段只要求完成：

- 读取比赛说明和数据。
- 自动生成任务说明。
- 完成 EDA。
- 训练 baseline。
- 生成 submission。
- 检查 submission 格式。
- 生成实验报告。
- 记录失败和下一步优化。

## 给老师汇报时的重点

我会说明：我已经看过 AutoKaggle、Agent K 和 AutoResearch AI 的方向。我的方案不是盲目复刻，而是先做一个轻量、可控、可复现的科研 Agent 工作站。

这个工作站第一步聚焦 Kaggle 表格任务，因为它有明确数据、指标和提交格式，最适合验证系统是否真的能完成数据科学任务。

等表格任务闭环跑通后，再扩展到老师给的科研案例、GPU 加速模型和更复杂的多模态任务。
