# 正式上线资源接入运行手册

本手册用于在拿到外部资源后，把科研 Agent 工作站从“本地可运行、外部资源待配置”推进到“真实 Claude Code / GPU / Kaggle 可验收”的状态。

## 当前状态

已完成：

- Titanic、House Prices、Telco Churn 三个 Kaggle 风格任务的本地训练闭环。
- 报告编辑、实验记录、完整性 Gate、动作日志、SQLite 状态和中文界面。
- Claude Code 后端接入底座：使用官方 Claude Agent SDK；缺少 key 时只返回 `not_configured`，不伪造成成功。
- GPU SSH 网关底座：只允许白名单训练模板，不开放任意 shell。
- Secret 读取：支持环境变量、`*_FILE` 和 `WORKSTATION_SECRET_DIR`。
- Docker Compose 已配置只读 secret 挂载路径 `/run/secrets/workstation`。
- 本机 DPAPI 启动器：`scripts\start_verified_workstation.ps1` 会在启动 Dashboard 前加载已安装的 DeepSeek / Claude / Kaggle 用户级加密凭据，并在启动后执行资源 smoke。

## Claude Code 接入

任选一种配置方式。

Windows DPAPI 方式（推荐）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\manage_claude_secret.ps1 install-key -ApiKey <rotated-anthropic-key>
powershell -ExecutionPolicy Bypass -File scripts\start_verified_workstation.ps1 restart -Port 8088
```

环境变量方式：

```powershell
$env:ANTHROPIC_API_KEY="<rotated-anthropic-key>"
```

文件方式：

```powershell
$env:ANTHROPIC_API_KEY_FILE="D:\secure\anthropic_api_key.txt"
```

安全要求：

- 不要把 API Key 写入 SQLite。
- 不要把 API Key 写入仓库文件。
- 之前聊天里出现过的明文 key 视为已泄露，正式使用前必须轮换。

## GPU SSH 接入

### HKUST(GZ) HPC 代理桥

校外访问 HKUST(GZ) HPC 时，先使用学校代理桥，不要改系统全局代理，也不要覆盖 NetCloudCore / Clash Verge 的端口。

当前本机约定：

- 本地桥：`127.0.0.1:7890`
- 上游 SOCKS5：`8.163.52.223:1080`
- 凭据存储：Windows 用户级 DPAPI 加密文件，不写入仓库
- PDF 官方 SSH 路径：`ncat --proxy 127.0.0.1:7890 --proxy-type socks5`

检查代理桥：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\manage_hpc_proxy_bridge.ps1 status
powershell -ExecutionPolicy Bypass -File scripts\manage_hpc_proxy_bridge.ps1 test
```

`test` 必须返回 `SSH-2.0-SSHPiper`，才说明校外到登录节点的网络层可达。

当前已配置的 SSH alias：

```text
Host hpc-hkust-gz
  HostName 100.85.169.63
  Port 1235
  User aimslab
  ProxyCommand ncat --proxy 127.0.0.1:7890 --proxy-type socks5 %h %p
```

如果登录节点返回 `Authenticated using "password" with partial success` 后继续要求 `publickey`，说明该环境账号不是单纯密码登录，而是要求“环境密码 + 已授权公钥”。此时不能把 GPU 自动作业标记为 ready，也不能把门户/HPC 平台账号当成 SSH 作业账号使用。

当前已验证事实：

- 门户/HPC 账号可用于平台登录、创建环境、打开 Web Terminal。
- 环境 SSH 账号用于进入具体 GPU 容器。
- 本机已生成专用 key：`C:\Users\景浩伟\.ssh\research_agent_hpc_ed25519`。
- 该 key 的公钥尚未被远端环境授权；本机现有 `id_ed25519`、`id_rsa`、`research_agent_hpc_ed25519` 均不能完成自动作业登录。
- 认证模式证据记录在 `workspace\hpc\ssh_auth_mode_20260613.json`。

下一步需要在平台 Web UI 里绑定公钥，或让管理员把 `research_agent_hpc_ed25519.pub` 加入该环境账号的授权 key。不要把环境密码写入工作站配置，不要用密码模拟自动作业。

给平台管理员或 Web UI 操作使用的最小申请包已生成：

```text
docs\HPC环境SSH公钥绑定申请包-20260613.md
```

### 通用 SSH 网关配置

如果平台绑定公钥或提供平台签发的环境私钥后，必须配置：

```powershell
$env:GPU_SSH_HOST="100.85.169.63"
$env:GPU_SSH_PORT="1235"
$env:GPU_SSH_USER="平台环境 SSH 账号"
$env:GPU_SSH_KEY_PATH="C:\Users\景浩伟\.ssh\research_agent_hpc_ed25519"
$env:GPU_REMOTE_WORKSPACE="/hpc2ssd/JH_DATA/spooler/aimslab"
```

建议配置：

```powershell
$env:GPU_SSH_KNOWN_HOSTS_PATH="D:\secure\known_hosts"
```

如果不配置 `GPU_SSH_KNOWN_HOSTS_PATH`，系统会在 artifact 中记录 host key 策略，不会静默伪装成已验证。

校外通过 PDF 代理路径运行 GPU Job 时，还需要让 dashboard 进程读取：

```powershell
$env:GPU_SSH_SOCKS_HOST="127.0.0.1"
$env:GPU_SSH_SOCKS_PORT="7890"
```

## DeepSeek / Kaggle DPAPI 接入

DeepSeek 已支持 Windows DPAPI，不要把 key 写进 `.env`：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\manage_deepseek_secret.ps1 install-key -ApiKey <rotated-deepseek-key>
powershell -ExecutionPolicy Bypass -File scripts\start_verified_workstation.ps1 restart -Port 8088
```

Kaggle 官方 API token 也使用 DPAPI；只有官方下载或官方提交时才需要配置：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\manage_kaggle_secret.ps1 install-token -Username <username> -Key <key>
powershell -ExecutionPolicy Bypass -File scripts\manage_kaggle_secret.ps1 smoke -AllowRealExternal
```

Kaggle 官方提交仍必须经过 Human Gate。本地 Kaggle-style 训练、validation gate 和 submission.csv 生成不依赖官方 token。

## 真实资源 Smoke Test

如果是在本机 PowerShell 中新增环境变量，先重启本地 Dashboard，让 Next.js 服务进程重新读取配置。正式本机启动优先使用统一 verified launcher：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_verified_workstation.ps1 restart -Port 8088
```

只做资源 smoke，不跑完整 acceptance：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_verified_workstation.ps1 smoke -Port 8088 -SkipFullAcceptance
```

如果是 Docker secret 或 `.env` 配置，先重建/重启容器：

```powershell
docker compose -p research-agent-workstation up -d --build
```

资源配置后运行：

```powershell
python scripts\run_real_resource_smoke.py --dashboard-url http://127.0.0.1:8088 --require-configured
```

该命令会：

- 以正在运行的 Dashboard 后端 `/api/workstation-summary` 为准判断资源是否已配置，兼容 Docker secret 和后台服务环境。
- 调用 Claude Agent SDK。
- 测试 GPU SSH 连接。
- 提交 GPU 白名单训练模板。
- 重新运行完整 acceptance。
- 写入 Action Log 和 workspace artifact。

资源未配置时可先运行：

```powershell
python scripts\run_real_resource_smoke.py --dashboard-url http://127.0.0.1:8088 --skip-full-acceptance
```

此时系统会明确列出缺少资源，并继续验证 `not_configured` 审计路径。

## 验收判定

- 未配置外部资源时：系统必须显示 `Not Configured` / `待配置`，并写入审计产物。
- 未配置外部资源时：不伪造成功，不显示为已接入、已提交或已完成真实外部训练。
- 配置 Claude 后：Claude 只能生成 transcript、patch、草稿和 manifest；必须经过人工 Gate。
- 配置 GPU 后：只能执行白名单训练命令；必须记录远程 provenance 和下载 artifacts。
- 配置 Kaggle 后：官方提交仍需人工 Gate，不自动伪装 leaderboard 成绩。

## Local Dashboard Lifecycle

如果不通过 Docker，而是在本机直接运行 Next.js 工作站，请使用统一管理脚本，避免手动 `npx next start` 留下多个后台进程。

正式演示 / 上线验证入口：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\start_verified_workstation.ps1 restart -Port 8088
powershell -ExecutionPolicy Bypass -File scripts\start_verified_workstation.ps1 status -Port 8088
```

这个脚本会先读取 `%APPDATA%\ResearchAgentWorkstation` 下已安装的 DPAPI 凭据，再调用 dashboard manager。它不会打印密钥；未安装的 Claude / Kaggle 会保持 `Not Configured`。

每次 `restart` 或 `smoke` 会写入不含密钥值的启动审计报告：

- `docs\verified_workstation_launch_audit.json`
- `docs\verified_workstation_launch_audit.md`

复验命令：

```powershell
python scripts\verify_verified_workstation_launch_audit.py
```

```powershell
python scripts\manage_workstation_dashboard.py start --port 8088
python scripts\manage_workstation_dashboard.py status --port 8088
python scripts\manage_workstation_dashboard.py restart --port 8088
python scripts\manage_workstation_dashboard.py stop --port 8088
```

脚本会自动设置 `WORKSTATION_ROOT`、`DATABASE_URL` 和 `NEXT_TELEMETRY_DISABLED`，并把运行信息写入：

- `web/research-agent-workstation/.runtime-logs/dashboard.pid`
- `web/research-agent-workstation/.runtime-logs/dashboard.out.log`
- `web/research-agent-workstation/.runtime-logs/dashboard.err.log`

启动后会检查 `http://127.0.0.1:8088/api/workstation-summary`，只有 summary 可读取且 runtime 状态存在时才报告 `started`。
