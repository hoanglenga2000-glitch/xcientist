# 科研 Agent 工作站任务规划书对照验收与差距

更新时间：2026-06-10

## 结论

当前系统已经不是纯静态展示页，具备本地数据任务运行、实验记录、验证 Gate、报告草稿、代码 Agent 补丁流和 SQLite 持久化能力。但如果严格对照《科研 Agent 工作站任务规划书（修订版）》，它还不能说已经完整达到“成熟 AI Data Scientist / Auto Research 系统”的状态。

更准确的定位是：第一阶段本地可运行原型已经基本成型，但仍需要继续加强“任务理解可视化、方案确认、失败自修复、跨任务通用性展示、真实外部 Claude Code 调用桥接和全站中文化”。

## 对照任务书验收

| 任务书要求 | 当前状态 | 说明 |
| --- | --- | --- |
| 真实数据任务闭环 | 已完成第一阶段 | House Prices、Titanic 等本地实验可运行，验证脚本通过。 |
| 任务理解 | 部分完成 | 有任务状态、指标、数据目录和风险记录，但 UI 还需要更明确展示“系统理解了什么”。 |
| 资料/文献调研 | 部分完成 | 有 research sources 和证据库，但尚未形成每个任务自动调研卡片。 |
| 方案设计 | 部分完成 | 有工作流和 Stage，但“执行前方案确认”还需要更明显的 Manual Gate。 |
| 数据分析与处理 | 已完成基础能力 | data_quality、EDA、实验产物已生成并进入报告/证据。 |
| 代码生成与运行 | 部分完成 | 已有 Code Agent 草稿、补丁导入、质量门；Claude Code 目前是安全 bridge mode，不是容器内直接执行宿主 CLI。 |
| 模型训练与验证 | 已完成第一阶段 | 本地 pipeline、指标、submission 检查和 validation gate 已跑通。 |
| 结果检查 | 已完成基础能力 | 行数、列名、缺失值、指标阈值等由 gate 检查。 |
| 实验记录 | 已完成基础能力 | SQLite、workspace artifacts、action log、experiment log 均有记录。 |
| 报告与复盘 | 部分完成 | 支持 AI Draft、在线编辑、图表插入、保存/导出；还需要进一步接近 Google Docs 的富文本体验。 |
| 人工审核 | 已完成基础能力 | Gate、Approve/Reject、补丁 Review/Apply/Rollback 已接入后端记录。 |
| 多数据类型扩展 | 未完成 | 当前主要是 tabular workflow，图像/文本/图结构仍是后续扩展。 |
| GPU / Kaggle 官方提交 | 受控未完成 | 按计划边界保持关闭，不伪装成已完成。 |

## 本轮新增修正

- 修复 Research Execution Graph 在窄容器中溢出到 Runtime Artifacts 的问题。
- 语言设置从“仅保存字段”改为驱动侧边栏、顶部栏、设置页、动作日志和关键运行卡片。
- 动作日志新增“发送给后端的内容”和“后端返回”，让每次点击变化可追踪。
- Code Agent 继续保留 Claude Code / Codex bridge mode，避免在未做安全桥接前伪造直接调用。

## 下一步必须补强

1. 任务理解页需要展示系统抽取出的目标、指标、文件结构、风险点和待确认问题。
2. 工作流页需要把“方案设计 -> 人工确认 -> 执行”做成强制路径，而不是只展示节点。
3. Code Runner 需要继续完善真实文件浏览、diff 对比、运行错误回放和修复建议。
4. Report Studio 需要加入更完整的富文本编辑体验、图表预览和 DOCX 导出质量检查。
5. 全站中文化还要覆盖所有静态文案，而不是只覆盖外壳和核心面板。
6. 如果要真正接入 Claude Code，需要做宿主 CLI 安全桥或外部任务队列，不能让容器直接无边界执行本机命令。
