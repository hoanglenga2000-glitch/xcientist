# Novice assistant quality gate: evidence fixture (suite v5)

Date: 2026-10-10. Applies to `configs/evaluation/assistant_novice_v1.json` v5 and later.

## What changed

* **v4 (model):** the gate measures the model the production web node serves:
  `deepseek-flash` via the pezayo OpenAI-compatible endpoint
  (`https://api.pezayo.com/v1`, `chat_completions`, 180 s timeout), the same
  route `bundle/scripts/Start-Node.ps1` configures. The suite pins it in
  `required_route`; `scripts/run_evomind_novice_quality_gate.ps1` reads the
  route credential from the current user's DPAPI store and exports it only to
  its own process. Earlier versions pinned `gpt-5.6-sol` on a loopback gateway,
  which production does not use.
* **v4 (hashes):** code and suite hashes are computed after normalising CRLF to
  LF. With `core.autocrlf=true` the same commit was checked out as LF, CRLF or
  mixed line endings, so byte hashes differed between the operator checkout
  and clean clones and the verifier rejected valid reports. Data artefacts keep
  byte-exact hashes.
* **v5 (evidence):** live cases no longer read the operator's `workspace/`.
  Each run materialises a hermetic workstation root from
  `src/xsci/assistant_quality_fixture.py` in a temporary directory, runs every
  case against it (`EVOMIND_WORKSTATION_ROOT`), records the fixture digest in
  the report, and deletes it afterwards. The verifier re-materialises the
  fixture and requires the digest to match.
* A case that exceeds the timeout is now scored as a failed case instead of
  aborting the whole evaluation without a report.

Thresholds are unchanged: every case must pass, mean score >= 0.85, p95
latency <= 90 s, report age <= 24 h, provider/model must equal the suite, no
unexpected or forbidden tools, governance unchanged, private grader executed
exactly once and failed closed, no official submission.

## Why

Up to v4 the gate depended on one historical Run,
`evomind_siim_isic_a800_job90353_20260730_095826`, in the operator's
`workspace/evomind_runs/`. That directory (with its private-grader ledger,
claim audit and candidate freeze) is no longer present on the operator
laptop. The project owner decided on 2026-10-10 **not** to recover it. Without
it the assistant had no verified evidence, fell back to searching the file
system, and the "grader executed exactly once" governance check could never
pass. Clean checkouts and staging builds never had that data either.

## What the fixture contains and where the values come from

| Item | Source |
|---|---|
| ROC-AUC 0.92254, PR-AUC 0.23971, Brier 0.29525, fold mean/std, patient cluster bootstrap 95% CI [0.91101, 0.93278] (2000 samples) | Values recorded for the historical Run in `scripts/verify_siim_job90353_goal.py` and `tests/test_assistant_context.py`. Reproduced, not re-measured. |
| Review checks (patient group overlap zero, content group overlap zero, OOF exactly once, ...) | Same recorded review of the historical Run. |
| Private grader: executed once, `failed_closed`, score null, not used for tuning; no official submission | Recorded governance state of the historical Run. |
| Literature: 10.1111/jdv.20479 (Kurtansky et al., JEADV 2024/2025) and 10.1016/j.media.2021.102305 (Cassidy et al., Medical Image Analysis 2022) | Real papers, verified against Crossref. |
| Four deliverables (`evomind-siim-isic-report.pdf`, `-results.csv`, `-code.zip`, `-evidence.zip`) | **Deterministic stand-ins generated by the fixture.** They are not the historical files; their sizes and SHA-256 prefixes are fixture-specific and pinned in the suite. |

The fixture Run is named `evomind_siim_isic_quality_fixture_v1` so that it
cannot be mistaken for the historical Run, and it only ever exists inside the
temporary evaluation root; it is never written into an operator or production
workspace.

## What the gate still proves

For each case the production assistant bridge (`python -m xsci.assistant_stream`)
runs end to end against the production model route. The assistant must take
its facts from `verified_context` / `experiment_results`, cite the recorded
metrics, explain patient/content grouped validation and leakage, cite the
reviewed literature, list hash-verified deliverables with download links,
respect "no training / no Kaggle submission" constraints across turns, and
never use file or shell tools for these read-only research questions.

It does not prove anything about the historical deliverable files, and it is
not an MLE-bench or official Kaggle result.

## Tool policy for evidence questions (same change set)

The first live run against the fixture (diagnostic `g1`, deepseek-flash) showed
the governance invariants passing, but every case failed the tool policy: with
`verified_context` already supplying the evidence, the model still browsed the
workspace with `file_list` / `file_read` / `file_search` / `shell_exec` (the
browser loop offered every core runtime tool on every turn). The file hunting
also pulled unrelated text into answers and cost the literature/grouping checks.

The fix is in the product, not the gate (`src/xsci/kaggle_conversation.py`):

- `_is_evidence_answer_turn` recognises a read-only question about governed
  research evidence (results, deliverables, literature, validation, next steps)
  that does not explicitly ask for local work (files, folders, code, scripts,
  commands, logs, terminal, a filesystem path or a source-file name).
- On such turns the web loop offers `verified_context` plus the focused research
  tools only; file/shell/process tools are not offered. Any explicit local-work
  request keeps the full core tool set, so general agent behaviour is unchanged.
- Defence in depth: in the web-safe loop a file/shell/process tool that was not
  offered on the turn is refused with a tool error instead of executed.

Tests: `tests/test_kaggle_conversation_tool_loop.py`
(`test_evidence_turns_hide_file_and_shell_tools_unless_local_work_is_requested`,
`test_web_loop_refuses_tools_that_were_not_offered_on_the_turn`, and the updated
selector/prefetch tests). Thresholds (0.85 per case, p95 <= 90 s) are unchanged.

## Temporary Claude gate route (operator-only)

When the production Pezayo `deepseek-flash` balance is exhausted, the novice
quality gate may be run against a temporary Anthropic-compatible NewAPI channel
(`api.lt4net.org`) using a local-only suite override and a DPAPI credential under
`%APPDATA%\EvoMind\secrets\` (filename prefix `newapi_lt4net_claude_temp`). The
committed suite remains pinned to production `deepseek-flash` / Pezayo. The
temporary override must not be committed, and the temporary key must be rotated
after the gate run. Production web continues to use Pezayo deepseek-flash.
