# 高级工具改版计划：从系统面板改为任务型产品

状态：待用户确认，尚未实施  
日期：2026-10-08  
范围：高级工具全部 12 页，以及完成入口整合所必需的导航、任务详情、成果和设置  
本轮交付：改版计划，不修改业务代码、不部署、不启动模型或训练

## 1. 目标与不做什么

用户能用自己的话描述需求，知道系统正在做什么、是否需要自己确认、最终在哪里查看结果。正常使用不要求先理解 Agent、DAG、Gate、manifest、handoff 或 HPC。

借鉴用户所说的 Codex 式体验：以任务和对话为入口，操作过程与结果围绕同一任务呈现，复杂信息按需展开。这是本产品的设计目标，不是对 Codex 当前功能的逐项比较，也不是复制其外观。

本次改版不能停在改名、换颜色、增加说明文字。必须补齐任务选择、需求输入、真实配置入口、失败恢复和结果回看。

不做：

- 不替换 Next.js/React 技术栈，不另建一套 UI 框架，不全站换肤
- 不重写训练引擎，不新增任意节点拖拽编排器，不建设新的插件或 Agent 平台
- 不通过扩大权限、自动批准、取消预算限制来制造“可用”
- 不删除历史任务、证据、模型、检查点或旧链接
- 不把只读核查或模拟运行说成真实模型、GPU、文献外部服务验收
- 不自动提交、部署、commit、更新长期项目记忆

### 已核对

- 当前公网版本：`overlay-invitation-beta-5141838f452e`；本轮健康读取为 `ready`

- 普通账户可安全读写的模型配置接口、资源配置权限与持久化范围

## 3. 推荐的信息结构

默认导航不再平铺 12 个高级工具。保留以下入口：

```text
＋ 新任务                 主按钮：描述需求、附加资料
我的任务                 最近任务；可按项目归类
资料与数据               上传、预览、关联到任务
文献检索                 搜索、导入、查看和使用论文
成果                     报告、文件、可比较的实验结果
设置                     模型、计算资源、预算、外观

任务内部
  对话                   输入需求、追问、确认方案
  进度                   当前步骤、需要处理的事项、失败原因
  文件与结果             预览、下载、来源；代码按需出现
  更多                   技术详情、日志、方案改进、旧记录
```

- 项目作为任务的归类方式保留，不要求用户先建项目才能提问
- 技术详情不是权限升级；普通用户只看有权限的当前任务信息
- 管理员排障入口放设置的“诊断信息”，不在普通任务首屏放全局运行时
- 旧入口和 URL 做兼容映射；不存在明确关联时给任务选择页，不能跳到任意第一条记录
- 普通页面不再悬挂不可操作的“未选择任务”横幅。需要任务时，就在该位置提供选择/创建入口

## 4. 全部 12 页如何处理

| 现有页 | 改版去向 | 普通用户要解决的问题 | 首屏内容与主操作 |
| --- | --- | --- | --- |
| 科研总览 `overview` | 并入“我的任务”概览 | 哪些任务在做、哪些等我处理？ | 最近任务、待处理事项；打开任务。全局设备健康不与个人任务混算 |
| DeepEvo 工作站 `control` | 并入任务“对话/进度” | 我要做什么，接下来怎么办？ | 用户需求、当前状态、一条下一步操作；旧 Scientist 面板移技术详情 |
| 任务队列 `tasks` | 并入“我的任务” | 找到、继续或查看某项工作 | 名称、状态、最近更新时间、结果入口；旧任务明确标历史来源 |
| 实验中心 `experiments` | “成果 → 实验对比” | 哪次实验更好，差在哪里？ | 选择同一任务的可比记录，显示指标名/方向/验证方式；打开结果或对比 |
| 文献 / RAG `literature` | 保留“文献检索” | 找论文并用于当前研究 | 搜索、导入、文献列表；任务选择可见。引用审核放选中后的详情 |
| 代码 Agent `code` | 任务“文件与结果 → 代码” | 描述代码需求、查看改动、检查并确认应用 | 需求框、代码范围、实际模型/模式、改动预览；模板与真实模型明确分开 |
| GPU / HPC `gpu` | “设置 → 计算资源”；任务内只显示所用资源 | 能否执行、在哪里配置？ | 未配置/待验证/可用/不可用及时间；有权限则配置，无权限说明管理员操作 |
| 流程编排 `workflow` | 并入任务“进度” | 正在做哪一步，为什么停下？ | 真实步骤时间线、失败原因、下一步；无执行记录就显示尚未开始 |
| 自进化引擎 `evolution` | 任务“更多 → 改进方案” | 能否在明确预算内尝试改进？ | 目标、基线、次数/时间/费用上限、计划预览；用户批准后才执行 |
| Agent 运行时 `runtime` | 任务“进度 → 详细记录” | 出错在哪里，发生了什么？ | 当前任务事件、工具操作、可理解错误；原始日志/ID按需展开 |
| 证据台账 `evidence` | “文件与结果 → 来源与验证” | 结果从哪里来，验证了什么？ | 文件名、来源、生成时间、校验范围；预览和下载，而非先显示哈希/内部ID |
| 完整性门禁 `gates` | 任务“待我确认”；列表显示待处理数 | 现在要我同意哪件事？ | 动作内容、影响范围、资源/费用上限、风险、拒绝后效果；同意/修改/拒绝 |

合并的是用户入口和重复视图，不是删除后台能力。涉及任务写操作时，始终展示正在操作的任务名称。

## 5. 统一交互规则

### 5.1 每页只回答四个问题

1. 这是什么任务或对象？
2. 目前是什么状态？
3. 我现在能做什么？
4. 做完后在哪里看结果？

首屏最多一个主操作。少量辅助操作可直接出现；技术操作与不常用操作放“更多”。不是每个页面都摆四块数字统计卡。

### 5.2 从任意入口进入都能开始

- 文献、代码、审批、进度等依赖任务的功能：就近提供搜索/选择任务
- 无任务时可“创建研究任务”；创建关联记录不应调用模型、消耗 GPU 或自动生成执行 Run
- 当前旧 Task 接口没有通用创建入口；若现有服务不支持，先设计最小、带所有权和幂等性的服务接口，不拿启动 Run 代替建空任务
- 有旧链接但记录无权访问：说明无权访问/已不存在，不回退到其他人的任务
- 切换任务、返回、刷新后，任务/Run/项目上下文保留；旧请求晚到不能覆盖新选择

### 5.3 术语改成具体意思

| 内部词 | 默认呈现 | 注意 |
| --- | --- | --- |
| Gate / Human Gate | 等待你确认 | 必须说清楚确认什么，不能只改中文标签 |
| WAIT_PLAN_GATE | 方案待确认 | 打开实际方案及该次确认记录 |
| blocked | 暂时无法继续：具体原因 | 分别说明缺资料、缺权限、预算不足、服务失败 |
| idle / reserved | 尚未开始 / 尚未执行 | reserved 是何种预留需按对象解释，不能一律当审批中 |
| DAG / handoff | 执行步骤 / 操作记录 | 原始拓扑只进技术详情 |
| artifact / manifest | 结果文件 / 文件清单 | 保留下载、版本与校验能力 |
| promoted | 已选为当前方案 | 不是官方排名，也不等于研究结论得到证实 |
| 证据血缘 | 来源与生成记录 | 能追溯，不要求用户先学习术语 |

执行完成、文件校验通过、模型质量通过、官方结果确认是不同维度，不压缩成一个绿色“成功”。未知、未检测、过期不能呈现为 0 或可用。

### 5.4 配置必须真能完成

设置分四组：模型服务、计算资源、使用预算、外观与语言。

- 每组显示当前值的安全摘要、权限、修改入口、保存状态、最近验证时间
- 明确区分“保存配置”和“测试连接”；测试若会调用模型或资源，事先说明副作用和费用，不能自动测试
- 秘密字段不回显、不写浏览器持久存储；复用受控加密提交/受保护存储
- 模型的用户级/项目级可配置能力本轮尚未证实；M0 必须给出真实能力表。若仅管理员可改，普通用户看到原因和管理员办理说明，不伪造可保存表单
- HPC 复用现有受控接入组件；从数据页迁入设置，并保留原入口跳转。不能改成普通 SSH 直连表单
- 预算继续显示可用量、已用量、修改影响、保存冲突；修改授权预算不能自动启动运行
- 用户从任务点“配置模型/资源”进入设置，完成后回到原任务和原输入，不丢草稿
- 不把外观保存按钮放在凭据区域，造成“保存了模型配置”的错觉

### 5.5 空、忙、失败、受限都要有下一步

- 空：一句说明 + 主操作；不展示一墙 0、破折号和审批术语
- 忙：显示正在做什么；仅在后端确实支持时提供取消/暂停，并说明状态
- 失败：保留输入；说明原因与可执行的恢复方式，技术错误码放详情
- 权限不足：说明需要谁处理；不能使用“服务故障”代替，也不能为修界面扩大权限
- 不支持：明确能力边界与替代路径；不能把没有后端的按钮做成能点击的占位控件
- 加载和页面切换本身不得派发模型、训练、审批或任务重试

## 6. 关键使用流程与可观察结果

| 场景 | 用户路径 | 完成标准 |
| --- | --- | --- |
| 第一次使用 | 新任务 → 描述需求/附资料 → 看建议方案 | 不要求填写内部 ID；缺配置时可直接处理；发送前不创建运行 |
| 找论文 | 文献检索 → 选择或创建研究任务 → 输入关键词 → 看结果 → 保存/用于任务 | 不再报裸 `invalid task_id`；有来源链接、可预览；检索失败可重试且不丢输入 |
| 修改代码 | 当前任务 → 代码 → 输入需求 → 看改动 → 检查 → 确认应用 | 用户能区分模板/真实生成；能看到具体改了哪里；未确认不应用 |
| 查看进度 | 我的任务 → 打开任务 → 进度 | 看得到当前步骤、阻塞原因、责任人和下一步；不固定高亮虚构步骤 |
| 处理确认 | 待我确认 → 阅读方案与影响 → 同意/拒绝 | 只影响目标任务和目标操作；拒绝可解释；重复点击不重复执行 |
| 配置资源 | 任务缺资源提示 → 对应设置 → 受控保存/验证 → 返回 | 原任务与草稿保留；没权限不能改；有配置不冒充已验证 |
| 查看成果 | 任务完成 → 文件与结果 → 预览/下载 | 下载的是所选 Run 的实际文件；刷新和历史回看仍能找到 |
| 改进方案 | 已有结果 → 更多/改进方案 → 设上限 → 预览计划 → 明确确认 | 未确认零执行；修改参数使旧确认失效；超限停止且保留已有结果 |

上述为验收目标，不是当前全部已经具备的能力。

开发预览里用独立、明确标注的样例数据；生产页面不能用同样样例冒充真实任务。计划本身不包含已完成的原型。

## 10. 验证方式与放行标准

验证模式：**TDD + 真实浏览器操作 + 普通用户可理解性验收**。前端与产品接口反馈快，适合短周期先失败后通过；这不能替代模型/GPU/外部服务的独立验证。

待用户批准实施时，同时确认以下测试边界；本轮不写测试、不启动测试服务：

- UI 公共行为：任务选择、输入、按钮状态、错误恢复、草稿保留、浏览器前进后退与刷新
- 已认证 API：所有权、任务/Run映射、保存后读回、幂等、预算冲突、审批过期、取消语义
- 交付物：从页面预览、下载实际文件并核对身份；不能只确认链接出现

### 技术检查

使用已存在命令，在隔离工作副本/数据库运行：

```powershell
# 前端目录
& 'D:/下载/npm.ps1' test
& 'D:/下载/npm.ps1' run typecheck
# 构建使用已验证的隔离发布工具；source receipt 由本次候选生成
# 仓库根目录
& './.venv/Scripts/python.exe' scripts/run_ci_checks.py --skip-tests
```

先为一个实际缺陷建立失败测试，再做最小修复。可复用 `status-truthfulness.test.mjs` 真实组件渲染方式；禁止只比源码字符串、重写实现逻辑作为期望、或 mock 内部整个组件来证明交互可用。

### 必须覆盖的情形

1. 新用户无任务、无项目、无模型配置
2. 直接访问每个旧链接；空/非法/无权访问的 task 和 Run
3. 两个任务来回切换、旧请求晚到、刷新、返回、历史 Run 回看
4. `401`、`403`、`409`、`5xx`、离线和超时；输入不丢，状态不误报
5. 模板与真实模型模式；真实服务不可用时不得偷偷降级伪装成功
6. 设置保存与读回、取消更改、无权限、预算冲突、从设置回原任务
7. 点击确认前不执行；重复点击不重放；改动预算/配置使旧确认失效
8. 审批拒绝、暂停/继续/取消仅在后端支持时展示且状态持久
9. 实验不同指标方向、数据集/划分/目标不一致时不比较；缺指标不补 0
10. 文件校验与科研结论分开；历史文件可预览下载，无跨用户泄露
11. 1366×768、1920×1080、390×844 布局；键盘导航、可见焦点、文字标签、读屏错误提示；技术长串不撑破页面
12. 暂停/恢复中任务及数据库历史在发布前后保持；无自动续跑或全局状态覆盖

### 普通用户验收：不能由测试数替代

建议邀请 3 名未参与开发的目标用户；若只能由项目负责人试用，报告必须标明样本限制。

不预先解释内部术语、不口头指路，给出五张任务卡：新建一个工作、找一篇论文、找到任务卡住原因、处理一项确认、找到并下载成果。

- 每名用户至少独立完成 4/5；所有关键步骤不能依赖开发者指路
- 每项入口应能在 30 秒内找到；从空状态开始的路径 2 分钟内能完成起步，不把模型等待时间计入
- 所有人在执行有费用/有写入影响的确认前，都能说明“会对什么任务做什么、上限是多少”
- 找不到入口、把模板当模型、把状态页当配置页、误认为批准会立即训练等，均记录为设计缺陷，不归因于用户不会用
- 未组织真实用户测试时，只能标“工程验收通过，可理解性待确认”，不能写“普通用户均能正常使用”

### 外部服务与上线

本轮计划不授权任何真实调用。实施中的模拟验收必须标注隔离夹具；真实文献搜索会保存记录，真实模型调用会计费，HPC 核验/训练/提交各自需要明确范围和授权。

HPC 操作前读 `docs/HPC_CONNECTION_MEMORY_CORE.md` 和机器契约，按 named DPAPI profile → 指定代理 → SSH gateway → allocation role → job container 核验。禁止直连私网地址或复用旧身份；规划和 UI 验收不需要执行 GPU 命令。

正式发布单独请求确认，复用既有 source receipt、build identity、服务器隔离验收、历史保护和 transaction 流程；重新生成计划 hash，不能复用旧发布 hash。上线后仍须真实登录走上述用户路径，不能只查 `/api/healthz`。

## 11. 交付物与验收责任

实施会话必须交付：

- 12 页迁移/能力矩阵，逐项列完成、部分、未动及证据
- 可交互的本地/隔离预览及入口，不提前替换正式网站
- 限定范围的源码、行为回归测试、迁移兼容说明
- 桌面/手机截图、关键操作记录、真实与模拟验证边界
- 用户可理解性测试记录，或明确待验证项
- `docs/plans/2026-10-08-advanced-tools-usability.report.md`

报告固定包含：完成情况总表、做了什么、没做什么与原因、规范遵循情况、特殊处理与偏离、遗留问题与建议。部分完成允许，但配置缺口不能通过隐藏功能或宣称高级用户专用来冒充完成。

执行者负责实现和工程验证；用户/目标用户负责产品方向与可理解性确认。收到报告后，本规划会话可按计划审查并另写 `.review.md`，不修改原报告。不自动新建会话、不派发执行代理；报告返回由用户触发。
