## 3. 本轮做了哪些实际修改

### 3.1 账号与数据，不让用户填写内部编号

- 增加受限 SQLite 账号登记：独立密码哈希、规范账号主体、角色、启停和会话版本。复用既有签名、CSRF 和来源校验，不开放公众注册。
- `WORKSTATION_ACCOUNTS_DB` 启用时，账号文件缺失或不合法即拒绝认证；不悄悄退回单一管理员密码。每次请求复核账号状态，停用/重置撤销旧会话。
- `manage_product_accounts.py` 为独立管理员工具，显式确认后才变更账号。只在隔离目录创建了 alice/bob；未运行任何生产账号命令。
- 新任务自动取得服务端 ID 和当前登录主体；草稿保存不建 Run、不调用模型。客户端伪造 owner/tenant 请求头不能认领他人内容。
- 新资料列表/下载 API 校验主体；任务选入资料时再次校验归属、任务版本及文件版本。其他任务不会自动继承附件。
- 每次运行复制冻结输入，修复原附件被重新绑定运行、硬链接导致原资料可被改写的问题。下载前验证实际字节、大小与 SHA256。
- 独立账号模式下，旧全局 Task、runtime、代码、文献等未完成归属约束的 API 拒绝访问；管理员身份也不会自动绕过新版个人边界。

### 3.2 工具权限：先限制危险能力

API 隔离还不够。红测证明，原有脚本工具能从当前运行读取另一个隔离目录。因此新增个人运行工具边界：

- 只允许已检查的文件、附件、发布交付物操作；路径必须在本次 Run 工作区内；冻结输入只读。
- 个人运行暂不开放 shell、任意脚本、进程、网络和 HPC 工具；即使获得普通审批也不能越过该边界。
- 这是**受限工具集合，不是操作系统沙箱**。完整代码执行、第三方工具和训练仍未迁完，不能声称已实现全能力多租户执行。
- 原管理服务路径未被直接改成个人权限；未借管理员凭据为普通用户执行。

### 3.3 页面主流程与恢复

- 根首页、登录后入口统一到 `/workspace`；六个主导航保留，项目变成可选组织方式。
- 设置分为“模型 / 计算资源与额度 / 账户与外观”；保存模型后可返回原任务，不再跳回旧设置外壳。
- 个人模型沿用前轮版本化 DPAPI 存储；保存、手动测试、任务实际使用分开显示。预览禁止外部连接测试，不自动切换平台模型。
- 计算资源仅读取本用户绑定；没有个人额度接口时显示“额度由管理员管理”，不把全平台预算当个人余额。不展示无权限的保存按钮。
- 对话、进度和结果使用所选任务/Run 的权威快照；运行选择保留原身份，已有 Run 只在显式、再次校验所有权后关联。
- 确认卡片列目标、风险、可恢复性、拒绝结果；确认框默认不选。普通显示改成任务内文件，内部绝对路径收进详情。
- 修复“暂停期间已批准，继续后仍卡在等待确认”：明确继续时复核原批准记录并只执行一次；不接受带新指令/凭据的旧批准续跑。
- 修复页面把 `recovering` 当结束态而关闭 SSE：恢复中继续接收事件，完成后无需刷新。暂停完成事件也更新页面。
- 断网/超时给出中文下一步，保留安全输入；重新读取版本不覆盖当前输入，再由用户决定保存。失败时不同时显示旧的“草稿已保存”。

### 3.4 发布与历史迁移拆开

`invitation_release_transaction.py` 的普通 CLI 路径不再执行历史 ownership migration、不再附带账号绑定或替换 ACL 文件；提案标记 `unchanged_no_migration`。新增任务/模型数据库进入保护清单。回滚只恢复代码与配置，不把新增用户数据回滚到旧副本。

隔离事务测试覆盖成功、预检失败、启动失败与恢复，检查 ACL、历史和新增数据保留。本轮**没有执行该脚本的生产 CLI**，包括非 `--apply` 模式；该模式仍有解包和预检写入，不视作只读命令。底层显式 ACL 参数保留给原有单独事务，未作为本轮授权使用。
