## 1. 要交付的产品

用户登录后，只看到自己的任务、资料、模型配置和成果。输入需求、可选附加资料，明确开始后，在同一个任务里对话、看进度、处理确认、下载结果。

不要求用户理解 Task、Run、Agent、Gate、manifest；不要求填写任务编号、服务器目录或历史关联字段。系统负责身份分配，用户只负责自己的工作。

已定规则：

- 按登录用户隔离；资料的已验证所有权用于校验能否加入任务，不通过资料名称反推用户
- 同一用户可明确选用自己的资料；不同任务的草稿、进度、审批和结果不互相混用
- 项目只是整理工具，开始任务不用先建项目
- 保留已确认的 8098 品牌与界面方向；不换技术栈、不全站重新设计主题
- 完整迁移仍覆盖原十二页能力，只减少一级入口、按需要展开复杂操作；隐藏按钮不算完成迁移
- 不新增团队共享、组织架构、自助公开注册、计费系统、微服务或每用户独立数据库

## 3. 用户最终看到什么

### 3.1 一级导航只保留六项

| 入口 | 用户能完成的事 | 不再默认展示 |
| --- | --- | --- |
| 新任务 | 写需求、可选附资料、开始或保留草稿 | Task ID、必填项目、科研执行内部参数 |
| 我的任务 | 找自己的工作、继续、看待处理与历史 | 全局任务队列、与自己无关的任务总数 |
| 资料与数据 | 上传、预览、管理自己的资料；选择用于哪个任务 | HPC 接入表单、全局文件目录 |
| 文献检索 | 输入关键词，选或创建自己的任务，检索、阅读、引用、导出 | 先手填任务编号、未选任务时仍能发出非法请求 |
| 成果 | 找报告、代码、数据和实验对比，预览/下载 | 没有文件的空统计大面板、把诊断文件叫科研成果 |
| 设置 | 模型、计算资源与额度、账户与外观 | 治理校验、内部状态面板、无权限的大段管理员表单 |

任务默认只有 **对话 / 进度 / 文件与结果** 三个视图。改进方案、历史记录与技术详情收进“更多”菜单；“待我确认”出现在任务内部，不再跳独立门禁页面。

### 3.2 一条简单主流程

1. 新任务输入需求，附件可选；草稿自动保存，不调用模型
2. 有可用模型时点“开始任务”；未配置时给“配置模型”入口，回来后保留输入
3. 运行时默认看回复，进度说明正在做什么或为什么停下；只有真实步骤，不预造进度百分比
4. 涉及花费或有风险的操作，卡片解释影响、上限和拒绝结果，用户明确确认
5. 有文件后出现预览与下载；文件属于哪次运行放在来源详情，不让用户找内部 ID

“开始任务”可在一个明确动作内完成草稿落库与执行提交；两个请求分别幂等。断网后先查原请求结果，不盲目重新执行。自动保存不是自动开始。

### 3.3 设置页收敛成三组

- **模型**：选择服务、模型名称、密钥；自定义服务才展开地址。保存、手动测试、设默认含义分开，测试明确提示费用
- **计算资源与额度**：自己的可用资源、当前任务批准上限、管理入口。没有配置就显示下一步；无预算修改权限只展示可读信息，不提供无效保存按钮
- **账户与外观**：当前账号、退出、必要的密码管理、语言、主题

禁止把全平台预算当个人余额展示。后端尚不能给出个人额度时，显示“额度由管理员管理”或已批准的任务上限，不编造剩余金额/时长。

状态用短句：尚未设置、尚未检查、可使用、暂不可连接。每个异常配一个明确动作；技术错误码放详情。“保存成功”不等于连接可用。

## 4. 身份与数据隔离：系统自动处理

### 4.1 先补真实独立登录

首版采用管理员开通独立账号的方式，不开放自助注册；复用现有密码哈希、会话签名、CSRF、来源和限流实现。普通用户角色与管理员操作边界由服务端决定。

新增受限账户记录，保存账号状态、密码哈希、规范主体和必要会话版本，不保存明文密码。首版登录名不可改；账号停用和密码重置使旧会话失效。实际生产账号创建、初始凭据发放和既有管理员配置变动另行授权；开发与验收先用两套隔离测试账号。

沿用现有 `tenant_id + owner_principal_id` 契约。当前 `owner_principal_id` 对应服务端规范账号名；保留既有主体与 tenant 值，不擅自改成新 UUID、按显示名重新计算或迁移历史。已有账号兼容需先明确验证。

### 4.2 统一所有权链

```text
登录会话确认的用户
  ├─ 我的资料、个人模型、项目
  └─ 我的任务
       ├─ 明确选入的本用户资料
       └─ 运行 → 进度 / 确认项 / 文件与来源
```

- 新任务由服务端分配真实 ID 和归属，不接受浏览器自报 owner/tenant
- 上传、分片、完成、预览、检索、引用、下载和删除都检查对象归属；列表为空不代表直接 URL 已安全
- 任务内选择资料再校验同一用户，并冻结本次输入版本；同用户其他任务文件也不自动拿来用
- 运行、SSE、审批、导出、缩略图、PDF、压缩包文件列表和下载沿同一归属检查
- 私有检索索引、缓存、计数、日志摘要也带用户范围；不能靠前端过滤。公共论文元数据缓存不包含私人上传、标注、密钥或聊天内容
- 模型工具只能读写该任务允许的工作区；API 隔离通过仍需验证工具不能读取另一用户文件
- 个人密钥继续使用已实现的版本化 DPAPI 存储；不扩大资源/预算权限，不让用户账号继承管理员的全部执行能力
- 退出或切换账号清理前端数据与待提交状态，关闭旧 SSE；迟到请求不得回填另一账号/任务。刷新只恢复状态，不重放动作

### 4.3 历史不交给普通用户猜归属

有权威 ACL 的历史记录可显示在“我的任务 → 历史”；点击继续或关联时再次核验，不因展示名称相同自动合并。

旧 Task 缺少归属证据时，保留原数据、限制普通用户访问，进入管理员待核实范围。上线不需要先猜完所有旧历史，但不能把这些记录开放给所有用户。界面隐藏与服务端访问限制必须一起做。

新文献/代码路径需要旧工具 Task 时，通过受控服务创建**真实、个人所属、与用户任务幂等绑定**的新记录；用户点“为本任务启用”即可，不手填 ID。历史回填是独立事务，不能夹在发布中执行。

| 步骤 | 对应原阶段 | 实施范围 | 完成标志 |
| --- | --- | --- | --- |
| P0 账号和数据边界 | M0/M1 | 独立登录；资料/任务/结果/模型隔离；旧入口后端权限；新旧 Task 桥 | 两个真实登录用户各建两任务，交叉读写、工具读取、SSE、下载均不能越权 |
| P1 一个完整外壳 | M1/M2 | 根首页、登录默认跳转、侧栏、设置、旧链接映射；不再回到旧复杂页面 | 从任意公开入口开始都回到同一套产品导航；可用键盘和手机操作 |
| P2 日常工作闭环 | M2/M3/M4 | 按下方路径逐条接真实能力，复用已有接口和控件 | 每项路径有用户操作、持久结果、失败恢复和归属证据，不只改名称 |
| P3 候选验收 | M5 | 限定构建、本地回归、服务器隔离验收、三人试用、发布/回滚演练 | 无越权/丢数据/重复执行；真实服务与模拟边界清晰；候选可复核 |
| P4 正式切换 | M5 | 展示候选、差异、验证和回滚；获该次确认后切换 | 线上真实登录验证，导航、历史、模型设置、任务、预览和下载通过 |

P0 不通过，不能先面向多个用户开放。P1/P2 可以逐条本地预览，但不能用“换成新版首页”代替功能完成。完整正式切换仍要求原十二页的能力有去处；如需先发布较小功能集，另列范围让用户确认，不自行删减。

### P2 的小步顺序

| 顺序 | 一条用户路径 | 必须保留的规则 |
| --- | --- | --- |
| 1 | 建任务 → 上传自己的资料 → 对话 → 暂停/继续或说明阻塞 → 预览下载 | 复用受控附件接口；保存不执行；操作只在后端支持时显示；失败保留安全输入 |
| 2 | 去设置配模型/资源/额度 → 保存 → 返回原任务 | 不丢草稿；无权限只读；模型测试与资源连接需明确动作；不悄悄换模型 |
| 3 | 文献搜索/导入 → 阅读 → 引用到任务 → 导出 | 独立入口；真实个人工具 Task；没有结果如实显示，不编造论文 |
| 4 | 描述代码需求 → 看差异 → 检查 → 确认应用/回滚 | 模板和真实模型分开；补丁目标归属和版本必须正确；不自动送 HPC |
| 5 | 查阻塞原因 → 理解待确认动作 → 同意/拒绝 → 看结果 | 确认绑定目标、参数版本、预算；参数变化使旧确认失效；重复点击不重复执行 |
| 6 | 成果比较 → 更多/改进方案 → 设置上限 → 看计划 → 明确批准 | 不混比数据/指标/验证口径；不默认训练；保留原结果；仅可验证能力允许执行 |

前五项是日常核心；第六项按需要出现，不恢复成一整列高级工具。技术日志和证据原文保留在详情，管理员诊断不放普通用户首页。

## 7. 验证方式与上线门槛

**验证模式：公共 UI / 已认证 API / 下载交付物边界的 TDD。** 本项目反馈快，最需要验证的是实际身份、状态与操作；一条路径一轮红→绿，再做浏览器验收。沿用已确认边界，不新增大而全的测试框架；只替换外部服务边界，不替换整个任务/权限系统。

上线必过：

1. 两个独立登录账号各有两任务；自己的内容可正常操作，换他人的 Task/Run/上传/文件/模型/审批 ID 全部拒绝，且不泄露名称、片段或计数
2. 重复发送、迟到响应、刷新、后退、换账号、会话到期、服务重启不串任务、不丢已保存内容、不自动续跑
3. 401/403/404/409、断网、超时、模型不可用、保存/上传/下载失败有清楚下一步；保留可恢复输入，密码和密钥不做浏览器持久化恢复
4. 手机真实菜单、输入、确认、返回和下载；桌面键盘全程可用、可见焦点与读屏标签。窄屏截图不能代替实际交互
5. 从页面下载实际文件，读取落盘文件核对内容、所属运行和哈希；后端下载成功不能替代浏览器下载验证
6. 服务器实际服务账户能加解密测试凭据，目录权限正确；模型保存/测试/运行使用分开验证。收费调用和真实资源验证另取授权
7. 发布前后用户、任务、运行历史、暂停状态、审批、交付物保持；没有自动续跑，没有历史归属回填
8. 至少三位目标用户不经口头指路完成：新建任务、找论文、找阻塞原因、处理确认、下载成果。记录完成情况、耗时、求助点；任一关键操作被误解或安全含义说不清，修复后重试，不拿测试数量替代

工程检查沿用本地已有命令：`npm test`、`npm run typecheck`、限定候选生产构建、`python scripts/run_ci_checks.py --skip-tests` 和相关 API 回归。完整命令和最终范围写进实施报告；验证正式包时不能只测含额外本地修改的工作树。

外部服务缺授权时：可以完成隔离开发，但对应真实服务状态仍为未验证，不能称全功能可生产使用。三个真实供应商协议分别登记结果；不可用的资源只显示正确的受限状态，不冒充已连接。

## 8. 发布与回滚

顺序：**限定源码 → 本地候选 → 服务器隔离候选 → 展示放行证据 → 用户确认该次切换 → 线上登录验收。**

- `build_invitation_release.py` 可作为现有构建入口研究与复用；调用前核对参数、基线和新 receipt，不照搬过期 hash
- `invitation_release_transaction.py` 当前含 ownership migration 和 ACL 替换；先实现并隔离验证纯代码/配置发布路径，不能直接沿用默认事务。其非 `--apply` 路径也有候选提取/预检行为，不当只读检查运行
- 服务器隔离环境只用测试账户、隔离数据和明确标记的外部替身；不能复制真实密钥到预览，不加载8098示例回复或本地测试启动器到生产
- 真实服务验证使用单独批准的测试范围/费用上限；HPC 验证先读指定连接核心并通过完整身份验证。计划与一般 UI 验收不要求操作 GPU
- 切换前短暂关闭新执行入口，等待现有活动操作安全结束，再核对未处理审批与状态；不强停任务、不代替用户批准。需要带暂停记录切换时，先通过相应恢复兼容验收
- 切换提案绑定候选 hash、数据结构、配置差异、验证结果和回滚目标；其中任一发生变化需重新核对，不能复用旧确认
- 新表/字段保持向后兼容，不删除历史；回滚恢复代码与配置，不覆盖用户数据数据库或新增运行/文件。旧版必须继续执行相同的账号隔离，不能通过回滚重新暴露旧全局列表
