## SSH 连接应该怎么做

PDF 给的是登录节点：

```powershell
ssh -o ProxyCommand="ncat --proxy 127.0.0.1:7890 --proxy-type socks5 %h %p" 【HPCSSH账号】@100.85.169.63 -p 1235
```

本地现在已经补齐官方 `ncat` 路径，并写入 `C:\Users\景浩伟\.ssh\config`：

```text
Host hpc-hkust-gz
  HostName 100.85.169.63
  Port 1235
  User aimslab
  ProxyCommand ncat --proxy 127.0.0.1:7890 --proxy-type socks5 %h %p
```

所以后续可直接使用：

```powershell
ssh hpc-hkust-gz
```

旧的 Python 代理桥仍可作为备用路径：

```powershell
ssh -o ProxyCommand="python D:\桌面\codex\科研港科技\scripts\hpc_socks_proxy.py 127.0.0.1 7890 %h %p" 【HPCSSH账号】@100.85.169.63 -p 1235
```

但创建开发环境后，平台卡片会给一个专属命令，例如当前 CPU 环境截图显示：

```powershell
ssh aimslab-chengtang-cpu2@10.120.18.240 -p 6988
```

这个 `10.120.x` 内网地址从校外 SOCKS 路径直接测试返回 SOCKS general failure / 超时。因此实际可行路径通常有两种：

1. 使用平台 Web 里的 `JupyterLab` 或 `Web终端` 直接进入环境。
2. 使用登录节点/平台提供的跳转方式进入环境；如果平台给了外部可达的转发地址，应以平台生成命令为准。

## 还需要你在平台里做的一步

如果你希望我真正 SSH 进去，还需要确认平台是否允许这个账号直接登录 `100.85.169.63:1235`。当前用已提供的 HPC 账号密码测试仍被登录节点拒绝，因此请优先走 Web 终端/JupyterLab，或在门户里确认：

1. 该账号是否已启用 SSH shell。
2. 是否必须先绑定 SSH 公钥。
3. 是否必须从平台环境卡片的 Web 终端进入后再跳转。
4. GPU 开发环境是否提供外部可达的端口转发地址。

Web 终端里请运行：

```powershell
whoami
hostname
pwd
python --version
nvidia-smi
df -hT
free -h
```

如果你不想把密码发出来，也可以在平台 Web 终端/JupyterLab 里自己运行上面的命令，把输出截图给我。

如果能复制文本输出，保存为本地文本文件后可用脚本校验：

```powershell
python scripts\verify_hpc_web_terminal_probe.py workspace\hpc\web_terminal_probe.txt
```

只有该脚本通过，且 `nvidia-smi` 文本能证明 4 张 A800 可见时，科研工作站才允许从 `GPU Environment Created / Web Terminal Ready / External SSH Pending` 升级为 fully ready。

本轮 UI 已按这个边界更新：HPC/GPU 不显示 `SSH Gateway Ready`，显示为 `GPU Environment Created / Web Terminal Ready / External SSH Pending`。平台页面显示的最强规格可以写作“4 x NVIDIA A800-SXM4-80GB、32 CPU、约 1TB RAM”，但在 Web 终端拿到 `nvidia-smi` 前，不能写成“4 x A800 已证实可用”。

## 后续接入科研工作站

一旦 GPU 环境 SSH 或 Web 终端验证通过，应把以下信息配置到科研工作站：

- `GPU_SSH_HOST`
- `GPU_SSH_PORT`
- `GPU_SSH_USER`
- `GPU_SSH_KEY_PATH` 或平台密码认证方案
- `GPU_REMOTE_WORKSPACE`
- `GPU_SSH_SOCKS_HOST=127.0.0.1`
- `GPU_SSH_SOCKS_PORT=7890`

然后运行：

```powershell
python scripts\verify_backend_resource_status.py --url http://127.0.0.1:8088
python scripts\verify_external_resource_gateways.py --url http://127.0.0.1:8088 --allow-real-external
```
