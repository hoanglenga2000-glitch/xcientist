# 实施路线图

## v1：跑通表格 Kaggle 闭环

目标：对标 AutoKaggle 的输入方式，完成一个表格类 Kaggle 或真实案例闭环。

交付物：

- `overview.txt` 或任务说明摘要。
- 数据概览文件。
- baseline 模型结果。
- submission 格式检查结果。
- 实验日志。
- 简洁报告。

验收标准：

- 能处理 `train.csv`、`test.csv`、`sample_submission.csv`。
- 有目标列时能训练 baseline。
- 无目标列时能完成 EDA。
- 能检查 submission 行数、列名和预测类型。
- 输出文件可追溯、可复查。

## v2：阶段化 Agent 流程

目标：把流程拆成背景理解、初步 EDA、数据清洗、深度 EDA、特征工程、建模验证和报告。

交付物：

- Reader、Planner、Developer、Reviewer、Summarizer 的职责说明。
- 每个阶段的输入、输出和检查项。
- 阶段报告。
- 单元测试清单。

验收标准：

- 每个阶段都能独立检查。
- 错误不会无记录地传递到下一阶段。
- 失败时能定位到具体阶段和原因。

## v3：加入 scaffold 与多轮改进

目标：吸收 Agent K 的 scaffold + post-scaffold 思路，先生成解题脚手架，再多轮改进。

交付物：

- 任务 scaffold：指标、验证方案、模型路线、风险点。
- post-scaffold 改进日志。
- 多轮实验对比。
- leaderboard 或本地验证分数记录。

验收标准：

- 每轮改进都有依据。
- 分数变化、错误变化和代码变化能对应起来。
- 能判断继续迭代还是停止。

## v4：接入 GPU 与高级模型

目标：把 GPU 用于真正需要算力的任务。

交付物：

- GPU 训练配置。
- 深度学习 baseline。
- 超参数搜索记录。
- CPU/GPU 训练对比。

验收标准：

- GPU 使用有明确任务和指标收益。
- 不为了展示而使用 GPU。

## v5：形成可复用科研 Agent

目标：把经验沉淀成可迁移的工作流。

交付物：

- 多任务实验模板。
- 常见失败案例库。
- 复盘报告模板。
- 可展示项目包。

验收标准：

- 新数据任务能复用已有流程。
- 报告、日志和代码结构稳定。
